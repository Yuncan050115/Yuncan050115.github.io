# 旧网站细节研究报告

旧站基于 Hexo 与 Butterfly，真正有价值的地方并不是某一个视觉组件，而是它把“博客是一个长期居住的空间”这件事做得很细。配置、生成页和前端文件共同组成了旧站的行为：文章来自 `_posts`，页面数据来自 `source/_data` 与插件生成结果，评论、播放器、右键菜单、昼夜切换、右侧工具栏、懒加载、封面兜底、版权声明都不是孤立功能，而是围绕阅读、浏览和停留形成的完整体验。

首先是导航。旧站顶栏和侧栏都采用分组菜单：文章下有归档、标签、分类；记录下有追剧、追番、游戏；社交下有留言板、友人帐；个人下有恋爱小屋、关于等。这个结构说明旧站并不是把所有页面平铺给用户，而是按“内容索引、生活记录、社交连接、个人信息”分层。新站如果把所有栏目放在顶栏，会立刻失去旧站的秩序感。因此本次重做把首页从导航中移除，把归档、标签、分类收入“文章”，把追番、追剧收入“在看”，把游戏改为“在玩”，把旧时光、恋爱小屋、关于收入“个人”。这比简单删减栏目更重要，因为它恢复了旧站原本的信息架构。

第二是背景和主题。旧站通过 `#web_bg` 做全局背景，而不是只在首页展示一张图。`source/js/fomal.js` 里还能看到浅色、深色背景变量，说明昼夜切换不仅改变文字颜色，也改变页面氛围。新站如果只在首屏放背景，离开首屏后整个网站就会断层。本次改动把 `https://apir.yuncan.xyz/index.php?size=1600` 作为全局 fixed 背景，并在浅色、深色主题上叠加不同透明遮罩；Three.js 画布也作为全局层存在，而不是某个页面的装饰。

第三是文章系统。旧站 `_config.butterfly.yml` 里启用了 toc、post copyright、封面兜底、错误图兜底等能力。文章末尾的作者、发布于、更新于、许可协议是旧站非常有温度的细节：它尊重内容的时间线，也明确创作边界。新站本次按旧逻辑补了文章目录、阅读进度条、正文图片兜底、封面兜底和版权信息框。封面处理也做了修正：有封面的文章优先出现在首页最近文章；无封面文章不再调用容易不稳定的随机图，而是使用站点 logo，保证稳定和识别度。

第四是评论。旧站评论不是随便塞一个容器，而是 `#post-comment` 包裹 `#twikoo-wrap`，再通过 Twikoo 初始化，并配合懒加载和评论数更新。新站之前只放 `#twikoo` 容器，容易和旧逻辑、样式、锚点脱节。本次恢复 `#post-comment` 与 `#twikoo-wrap`，云函数使用用户指定的 `https://comment.yuncan.xyz`，并在 Astro 页面切换后按当前 path 重新初始化，避免同站内路由切换后评论不显示。

第五是媒体记录。旧站追番、追剧、游戏并不是手写空页面。`source/_data/bangumis.json` 和 `cinemas.json` 是旧构建缓存，而生成页里能看到 Steam 游戏库的真实条目、Steam 商店链接、论坛、社区、官网、新闻和 SteamDB 链接。B 站接口可以通过 `https://api.bilibili.com/x/space/bangumi/follow/list?vmid=189708807&type=1` 读取追番，通过 `type=2` 读取影视记录。Steam 社区 XML 现在会跳登录，所以新站先解析旧生成页作为真实静态兜底，同时把 Steam API Key 留在 `src/config/yuncan.config.ts` 里，后续可扩展为构建时刷新。图片显示问题也要注意 B 站防盗链，因此媒体图片统一加 `referrerpolicy="no-referrer"` 和 logo fallback。

第六是播放器。旧站启用了 APlayer/Meting 注入，说明音乐是全站级体验，不应随着页面切换中断。用户给出的 `music.yuncan.xyz` 是 MetingJS 格式接口，歌单 id 是 `817519033`。测试后确认接口能直接返回 title、author、url、pic、lrc。新站播放器因此改为从配置读取 Meting 参数，拉取真实歌单，解析歌词 URL，并用 `transition:persist` 保持 audio 和播放器节点不随 Astro 页面切换销毁。视觉上也从左下角大白块改成轻量胶囊，默认收起，播放或 hover 时展开。

第七是全局工具。旧站右侧工具栏有昼夜切换、右键模式、分享、评论、回顶、到底部等；右键菜单还包含后退、前进、刷新、回顶、复制、搜索、空降评论、复制本文地址、阅读模式、全屏、打印等。这些功能让博客像一个小系统，而不是纯静态页面。本次新站先实现了全局自定义光标、右键菜单、复制地址、空降评论、昼夜切换、打印、回顶、FPS 显示和阅读进度。后续可以继续补“随机文章”“全屏”“阅读模式”等动作，但第一版应先保证轻量、稳定、不臃肿。

第八是动效。旧站的细腻感来自持续的小反馈：hover、懒加载、昼夜切换、右侧按钮、滚动提示、卡片抬升。新站要有 2026 的高级感，不能靠堆阴影和大渐变。更合适的方向是统一缓动、透明层级、低对比呼吸、滚动吸附、页面切换不打断全局状态。本次 Three.js 从线框球改为 shader 呼吸场加粒子层，配合全局背景、毛玻璃导航和卡片进入动画，让“呼吸感”贯穿全站。

最后是配置治理。旧站好维护，是因为 Hexo 和 Butterfly 把大量行为放进配置。新站也不能把接口散落在组件里。本次新增 `src/config/yuncan.config.ts`，集中放站点信息、背景、logo、Twikoo、音乐、B 站 UID、Steam ID、Steam API Key、导航、许可协议和项目入口。以后真正需要用户改的内容，都应该先进入 config，再由页面消费。这样站点才能既保持动效丰富，又不变成难以维护的大杂烩。
